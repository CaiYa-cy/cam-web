# 云端服务器网页与ESP32双向通信方案

## 1. 系统概述

### 1.1 当前架构

`
┌─────────────────┐   SPI (从机)     ┌──────────────┐
│   主机设备 (MCU)  │ ──────────────▶ │  ESP32-C3    │
│   (SPI 主机)     │ ◀────────────── │  (SPI 从机)   │
└─────────────────┘                  └──────────────┘
                                          │
                                     WiFi STA 模式
                                     (按需开关)
`

- ESP32-C3 作为 SPI 从机，接收主机设备发来的 128 字节数据包
- 数据通过 DMA 环形缓冲区接收，在 loop() 中轮询处理
- 现有协议：CMD=0x10（数据更新）、CMD=0x20（系统控制）、CMD=0x30（状态查询）
- WiFi 由主机通过 SPI 指令（CMD=0x20）远程开关
- 原设计自带 WebSocket 服务端+HTTP 服务端（现已废弃此架构）

### 1.2 目标架构

`
┌──────────────┐   SPI           ┌──────────────┐  HTTP POST/Resp  ┌─────────────────┐  WebSocket  ┌──────────┐
│ 主机设备(MCU) │ ◀─────────────▶ │  ESP32-C3    │ ◀──────────────▶ │  腾讯云服务器     │ ◀──────────▶ │  浏览器   │
└──────────────┘                 └──────────────┘                  │ 124.222.148.162 │             │  (网页)   │
                                                                  └─────────────────┘             └──────────┘
`

- ESP32-C3 不再运行本地 Web 服务器，改为 **HTTP Client** 模式
- 每 500ms 向云服务器 POST 传感器数据，同时在 HTTP 响应中获取待执行指令
- 云服务器上运行一个 Python 中转服务，负责 WebSocket ↔ HTTP 双向转发
- 浏览器通过 WebSocket 实时接收数据、发送控制指令

## 2. 双向通信机制

### 2.1 上行通道：ESP32 → 云端 → 网页（数据上报）

`
ESP32-C3                         云服务器                          浏览器
   │                                │                                │
   │  POST /update                  │                                │
   │  {"progress":"25/100", ...}    │                                │
   │ ─────────────────────────────▶ │                                │
   │                                │  广播 WebSocket                │
   │                                │  {"progress":"25/100", ...}    │
   │                                │ ─────────────────────────────▶ │
   │                                │                                │ updateUI(data)
`

**触发条件**：每 500ms 定时上报一次  
**数据格式**：与现有 uildDataJson() 输出完全一致
`json
{
  "t": 1234567,
  "progress": "25/100",
  "status": "SMTing",
  "heater_on": 1,
  "heater_temp": 150.0,
  "fault": "00",
  "wifi": 1,
  "spi": 1
}
`

### 2.2 下行通道：网页 → 云端 → ESP32（指令下发）

`
浏览器                          云服务器                          ESP32-C3
   │                                │                                │
   │  WebSocket                     │                                │
   │  {"cmd":"wifi_on"}             │                                │
   │ ─────────────────────────────▶ │                                │
   │                                │  加入指令队列                   │
   │                                │                                │
   │                                │  POST /update                  │
   │                                │ ◀───────────────────────────── │
   │                                │                                │
   │                                │  HTTP 200 OK                   │
   │                                │  {"commands": [           │    │
   │                                │    {"cmd":"wifi_on"}]     │    │
   │                                │ ─────────────────────────────▶ │
   │                                │                                │ 执行指令
`

**关键设计**：指令**不单独建立通道**，而是利用 ESP32 已有的 500ms 上报周期"搭车"返回。  
**优点**：
- ESP32 端代码改动最小（只需在 POST 后读取响应体）
- 无需 ESP32 维护 WebSocket 长连接，节省内存和功耗
- 500ms 延迟对控制类指令完全可接受

## 3. 云服务器中转服务设计

### 3.1 技术选型

| 项目 | 选择 | 理由 |
|------|------|------|
| 语言 | Python 3 | 服务器已有，无需额外安装运行时 |
| Web 框架 | iohttp | 同时支持 HTTP + WebSocket，异步高性能 |
| 数据存储 | 内存队列 collections.deque | 指令暂存，无需持久化 |

### 3.2 端口规划

| 端口 | 服务 | 说明 |
|------|------|------|
| 80 | Nginx | 静态网页 SMD_Monitor.html |
| 8080 | Python 中转服务 | HTTP POST + WebSocket |

### 3.3 核心逻辑

`python
# relay_server.py  - 核心伪代码

commands_queue = deque(maxlen=10)   # 待执行指令队列
ws_clients = set()                  # 连接的浏览器

# WebSocket 端点: /ws
async def ws_handler(request):
    ws = web.WebSocketResponse()
    await ws.prepare(request)
    ws_clients.add(ws)
    try:
        async for msg in ws:        # 浏览器发来的指令
            cmd = json.loads(msg.data)
            commands_queue.append(cmd)  # 加入待执行队列
    finally:
        ws_clients.discard(ws)
    return ws

# HTTP POST 端点: /update  (ESP32 调用)
async def update_handler(request):
    data = await request.json()

    # 1. 广播数据给所有浏览器
    for ws in ws_clients.copy():
        await ws.send_json(data)

    # 2. 返回待执行指令
    if commands_queue:
        response = {"commands": list(commands_queue)}
        commands_queue.clear()
    else:
        response = {"commands": []}

    return web.json_response(response)
`

### 5.2 WebSocket 连接代码

`javascript
var ws;

function connect() {
    ws = new WebSocket("ws://124.222.148.162:8080/ws");
    ws.onopen = function() {
        document.getElementById("wifiDot").className = "status-dot status-dot--on";
        document.getElementById("wifiText").textContent = "云端已连接";
    };
    ws.onclose = function() {
        document.getElementById("wifiDot").className = "status-dot status-dot--off";
        document.getElementById("wifiText").textContent = "云端断开";
        setTimeout(connect, 3000);
    };
    ws.onmessage = function(e) {
        try { updateUI(JSON.parse(e.data)); } catch(ex) {}
    };
}

// 发送指令
function sendCommand(cmd) {
    if (ws && ws.readyState === WebSocket.OPEN) {
        ws.send(JSON.stringify({ cmd: cmd }));
    }
}
`

## 6. 指令协议设计

### 6.1 网页 → 服务器指令格式

`json
{ "cmd": "指令名", "params": { "key": "value" } }
`

### 6.2 服务器 → ESP32 指令格式

`json
{
  "commands": [
    { "cmd": "wifi_on" },
    { "cmd": "set_param", "params": { "target_temp": 200 } }
  ]
}
`

### 6.3 支持的指令列表

| cmd | 参数 | 说明 | ESP32 执行动作 |
|-----|------|------|----------------|
| wifi_on | 无 | 开启 WiFi | wifi_enabled=true; WiFi.begin(ssid,password) |
| wifi_off | 无 | 关闭 WiFi | wifi_enabled=false; WiFi.disconnect(true) |
| query_all | 无 | 查询全部 | 立刻 POST 一次完整 JSON 到 /update |
| query_fault | 无 | 查询故障 | 通过 SPI 回复 RSP_FAULT，或 HTTP 响应中带回 |
| spi_cmd | {cmd, sub, payload} | 自定义 SPI 指令 | 封装为 SPI 包通过 	x_buffer 发给主机设备 |

## 10. 注意事项

1. **ESP32 内存**：删除 WebSocket/HTTP 服务端库后，可释放约 30-40KB RAM，HTTPClient 只需约 5KB
2. **断电保护**：ESP32 重启后指令队列丢失是正常行为，重要指令建议网页端增加确认机制
3. **WiFi 依赖**：下行指令完全依赖 ESP32 的 WiFi 连接，WiFi 断开期间指令会在服务器队列累积（队列最大 10 条）
4. **安全**：当前无鉴权机制，适合内网或信任环境。如需公网使用，建议在 Nginx 层加 Basic Auth 或转用 HTTPS+WebSocketSecure
